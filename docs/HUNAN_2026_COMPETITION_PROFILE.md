# 湖南赛区定制规则 Profile — 2026
## 本 Skill 的实际执行优先级

本工作流专门服务当前参赛场景，因此在不触碰全国竞赛实质性违规底线的前提下，
**采用已由用户确认的湖南赛区实际执行口径作为本仓库默认硬规则。**

优先级：

\[
湖南赛区当前确认执行口径
>
全国通用默认排版建议
>
培训/一般经验
\]

若赛区后续发布新的正式通知，以最新赛区通知再次覆盖。

---

# 1. 页码规则【HUNAN HARD RULE】

本工作流执行：

```text
摘要专用页：不显示页码
正文第一页：页码 1
正文后续：连续编号
附录：接正文连续编号
```

因此不采用全国通用格式文本中“摘要页为第1页”的默认理解。

LaTeX 模板必须显式实现：
- 摘要页 `\thispagestyle{empty}` 或等效处理；
- 正文开始执行 `\setcounter{page}{1}`；
- 页码位于页脚中部；
- 默认不设置页眉。

---

# 2. 页数规则【HUNAN HARD RULE】

本工作流采用以下赛区控制目标：

```text
摘要：1页
正文主体 + AI工具使用声明 + 参考文献：<=30页
附录：<=20页
整体主论文PDF：目标 <=51页
```

正文推荐：
> **29页或30页**

但“接近30页”必须通过有价值内容实现：
- 更完整的问题分析；
- 数据结构发现；
- 模型推导；
- 算法说明；
- 结果证据；
- 消融/敏感性/验证；
- 高质量图表。

禁止为了凑页数加入：
- 重复背景；
- 空泛综述；
- 无意义图；
- 重复结果表；
- 与模型无关的算法百科。

附录必须在20页内完成完整代码呈现，因此代码工程需要在赛中保持：
- 模块清晰；
- 删除废弃实验代码；
- 去除冗余调试输出；
- 不重复粘贴相同函数；
- 注释简洁但足以理解；
- 最终提交代码与实际运行版本一致。

---

# 3. 附录代码规则【HUNAN HARD RULE】

论文附录必须放：

> **全部最终建模与计算所使用的完整、可运行源程序代码。**

不是只放“核心代码”。

正文中：
- 只展示伪代码、关键流程或少量核心片段；
- 不把大量实现代码塞入正文。

附录中：
- 按文件/模块顺序给出完整代码；
- 每个代码文件前给一行用途；
- 代码版本必须与支撑材料一致。

支撑材料中：
- 同时放原始 `.py` / `.m` / `.R` / `.ipynb` / 其他可运行文件；
- README 说明运行顺序；
- requirements/environment；
- 输入输出路径；
- 随机种子。

如果完整代码超过20页：
> 优先重构、删除无关调试/废弃代码和重复实现；
> 不允许通过“只截核心代码”解决页数问题。

---

# 4. PDF 规则【HUNAN HARD RULE】

本工作流不把“非图片PDF”当建议，而直接作为提交硬标准：

> **最终论文必须使用原生可检索文本 PDF，不允许整篇图片化/扫描式 PDF。**

推荐并默认：

\[
\boxed{\text{LaTeX source} \rightarrow \text{PDF}}
\]

要求：
- 正文文字可搜索；
- 文字可复制；
- 数学公式由 LaTeX 排版；
- 表格由 LaTeX 原生生成；
- 矢量图优先 PDF/SVG→PDF；
- 必须使用位图的图像使用高分辨率 PNG/JPG；
- 不把整页论文截图再拼成 PDF；
- 不将 Word 页面逐页转图片；
- 字体正确嵌入；
- PDF 打开后无乱码；
- 文件满足竞赛大小限制。

提交前执行：

```text
Text selectable:
Search works:
Fonts embedded:
No page-as-image:
Equations sharp:
Vector plots where applicable:
File opens:
File size compliant:
PASS/FAIL
```

FAIL 时不得提交。

---

# 5. LaTeX 作为默认论文生产环境【HUNAN DEFAULT】

除非出现必须使用 Word 的官方特殊要求，否则：

> **默认使用 LaTeX 编写和生成最终论文。**

原因：
- 公式一致；
- 编号/交叉引用稳定；
- 图表位置可控；
- 参考文献编号可自动维护；
- 页数和附录代码更易控制；
- 更容易生成原生非图片PDF。

建议项目结构：

```text
paper/
├─ main.tex
├─ sections/
│  ├─ abstract.tex
│  ├─ problem.tex
│  ├─ analysis.tex
│  ├─ model_q1.tex
│  ├─ model_q2.tex
│  ├─ model_q3.tex
│  ├─ validation.tex
│  ├─ conclusion.tex
│  └─ appendix.tex
├─ figures/
├─ tables/
├─ code/
├─ references.bib
└─ build/
```

参考文献正文编号：
- 使用统一 BibTeX/BibLaTeX 或等效方式；
- 正文按 `[1]`、`[2]` 等实际引用；
- 文献必须先核验真实性；
- AI工具本身不自动列为参考文献。

# 6. AI 相关规则

保持 V4.3.2 的判断：

- AI 工具本身不要求列为参考文献；
- 参考文献之前放 AI 工具使用声明；
- 使用 AI 时支撑材料必须包含 `AI 工具使用详情.pdf`；
- 不要求自行上传第三方做 AIGC 率检测；
- 不把论文上传未知第三方查重/AIGC平台；
- AI 输出必须人工逐项核验；
- 核心建模与分析由参赛队主导。
